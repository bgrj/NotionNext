# 我们的存在：活动、预约与吾在原生小程序

日期：2026-11-24。目标分支：`bgrj/NotionNext:ourbeings.com`。

## 设计与范围

保留网站首页四区、上下手背景、现有登录与私人空间。只在「我们的存在」内部，把活动从介绍文章推进为可发布、可预约、可交流的完整流程。延续网站纸感、棕金与衬线标题，不使用演示活动冒充真实数据。

公共入口保留「阅读活动 / 公开内容」；活动页提供即将相遇、往期相遇、我的活动及线上/线下筛选。活动包括书名或主题、介绍、开始与结束、截止时间、人数、地点和交流方式。先保存私密草稿，再由发起人明确发布。活动通知在详情页展示；这不是微信订阅消息推送。

网页中的站内活动，发起人与已预约者可以进入独立交流群；微信活动直接使用发起人建立的微信群，预约后显示入群说明。取消预约立即撤回私密说明与站内群的访问资格。站内群保留最近 100 条文字，通知保留最近 30 条。活动取消后停止预约与群发言，既有参与者仍可查看通知与归档交流。

## 原生包与参考项目

`apps/wuzai/` 是可独立复制的微信原生工程，不依赖 Next.js、React、DOM 或网站编译产物。`project.config.json` 指向 `miniprogram/` 和 `cloudfunctions/`。提供相遇、详情、发布、我的活动、隐私说明五页，使用原生导航栏、picker、textarea、分享与云函数调用。

参考 `D:\02_Dev\Our-Being` 的活动列表、当前/历史筛选、活动表单、详情与我的活动流程。沿用参考项目的公开 AppID 和云环境配置作为起点，不修改该目录，不复制其本地配置改动、密钥、个人创作或旧云数据库。新云函数名为 `wuzaiApi`，不会替换旧 `activityService`。

旧字段的对应关系如下，仅用于将来显式迁移，不自动导入历史数据：

| 参考项目                               | 当前活动模型                                           |
| -------------------------------------- | ------------------------------------------------------ |
| `_id`                                  | `id`，新活动 UUID，不复用旧库 ID                       |
| `date`、`time`、`registrationDeadline` | `startsAt`、`endsAt`、`deadline`，含时区的 ISO 时间    |
| `maxParticipants`                      | `capacity`，1–500，不含发起人                          |
| `isOnline`                             | `format: online / offline`                             |
| `meetingLink`、`contactInfo`           | `joinInstructions`，仅预约后可见                       |
| `status: 1 / 0`                        | `state: draft / published / cancelled`，再派生活动状态 |

不沿用先查人数再写入的旧预约方式，不把旧库的手机号或联系资料自动带入新公共页面。

## 复用结构与接口

纯 JavaScript 规则在 `apps/wuzai/miniprogram/common/activities.js`。网站和微信页面共用校验、时间展示、活动状态等规则；服务端再次执行所有关键校验。

统一接口：`/api/our-beings/v1`。读操作为 GET，也接受经签名的云函数 POST；写操作只能 POST。返回 `{ version: 1, event/events/messages, ... }`；失败返回明确 HTTP 状态与 `{ error, message }`。

| action                                                 | 用途                           | 权限                 |
| ------------------------------------------------------ | ------------------------------ | -------------------- |
| `list`, `get`                                          | 已发布活动列表、详情、公开通知 | 访客可读，草稿仅本人 |
| `mine`                                                 | 本人发起和预约历史             | 本人                 |
| `create`, `edit`, `publish`, `cancelEvent`, `announce` | 草稿、安排、发布、取消、通知   | 已登录；管理仅发起人 |
| `reserve`, `cancelReservation`                         | 预约与退出                     | 本人                 |
| `messages`, `message`                                  | 站内活动群                     | 发起人或已预约者     |

网站身份从 Clerk 服务端会话派生。微信云函数从 `cloud.getWXContext()` 取得 APPID/OPENID，忽略客户端提供的身份；以 HMAC、时间窗与一次性 nonce 验证到网站的请求。密钥只存在云函数和网站的服务端环境。网页不能自报 OPENID。微信提交的活动与通知经云函数文本检查后才转发。

身份分别为 `clerk:<id>` 与 `wx:<appid>:<openid>`。当前不合并账号、不假设 UnionID 必然存在、不因相同昵称或邮箱自动绑定。未来绑定需要双方完成身份验证。跨端共享活动数据不等于跨端共享登录状态；站内群仍需已预约的网站账号。

## 数据与并发

复用网站已有 `REDIS_URL`，业务键使用独立前缀 `wuzai:{activities:v1}:`，不设业务记录 TTL，不调用现有缓存清理流程。单个活动聚合保存安排、预约、通知与最近交流。

更新由读取原记录、纯规则转换、Lua compare-and-set、冲突重试完成，活动与本人索引在同一次 Lua 操作中更新。名额判断与写入因此不会分离。重复预约不重复占位，取消会释放名额，已有预约时不允许把人数降到已预约人数以下，也不允许更换交流方式。

部署前应确认 Redis 持久化、容量与备份策略；应用不创建新付费数据库，不声称已审计当前托管服务的数据持久性。长期增长后可以用 repository adapter 迁移到专用数据库，页面和接口不需要重写。活动数据包含真实业务记录，不能按缓存批量清空。

## 独立复制与微信发布准备

1. 将整个 `apps/wuzai/` 目录复制为独立工程，在微信开发者工具中导入；确认 AppID 为自己的小程序。默认 AppID 来自参考项目。
2. 确认 `miniprogram/settings.js` 的云环境；上传新函数 `wuzaiApi`，选择云端安装依赖，不覆盖旧 `activityService`。SDK 固定为已核对 npm 官方包的 `4.0.2`，发布前在真实云环境回归。
3. 网站服务端设置 `WUZAI_MINI_APP_ID`；网站与新云函数分别设置相同的随机 `WUZAI_MINI_BRIDGE_SECRET`。云函数可设置 `WUZAI_API_ORIGIN=https://ourbeings.com`。不要把密钥放进原生客户端或 Git。
4. 确认云函数有 `security.msgSecCheck` 权限，文本检查正常；网站已有可用 `REDIS_URL`。未配置桥接密钥时，小程序如实提示服务未就绪，不生成虚假预约。
5. 在 `settings.js` 填写运营方真实支持联系方式，完善微信后台的隐私指引、主体资料与服务类目，并在真机验证发布、预约、取消、通知和分享，再提交审核。

本次交付原生源码与云函数入口，不等同于已经上传微信云函数、完成真机回归、提交审核或获得审核通过。微信订阅消息、主动身份绑定、支付、媒体上传、原有云库迁移不属于本次启用范围。

## 验证与发布

Windows 本地构建若遇到内存不足，可设置 `LOCAL_LOW_MEMORY_BUILD=true`，使用两个静态生成 worker、Webpack 独立构建 worker 和内存优化；未设置时维持原有生产配置。此选项不更改路由或视觉样式。参考 [Next.js 构建内存说明](https://nextjs.org/docs/app/guides/memory-usage)。

执行 `node scripts/check-wuzai-package.js` 检查原生 JSON、JS、页面路径与 WXML 事件绑定；Jest 验证草稿隔离、白名单、所有者权限、跨端身份、20 人并发抢 2 位、重复预约、退出撤权、时间边界、通知与桥接防重放。

浏览器验证活动入口、列表筛选、详情、预约交互与手机布局。使用测试替身的数据必须明确仅限本地 QA；生产不写入演示活动。生产构建后推送目标分支，确认 Vercel 项目 `ourbeing` 对应提交为 READY，再检查正式域名和匿名接口。

当前网站原有的 5 个本地未提交文件保持原样，不纳入此功能提交。回退可 revert 本次功能提交；保留新业务键，以免回退源码时删除用户预约。
